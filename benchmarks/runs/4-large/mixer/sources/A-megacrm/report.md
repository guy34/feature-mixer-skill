## Summary

MegaCRM is a small Python CRM core: contacts (create, search, merge duplicates),
a deals pipeline with five fixed stages, and whole-table CSV export. The
repository is large by file count (408 indexed files, 25 modules) but 400 of
those files sit in 20 `gen_*` modules of generated plumbing with no
user-facing behaviour; the real features live in four small modules. The
data-access helper is a stub (`NotImplementedError`), there is no HTTP layer,
no auth and no UI source, although `package.json` declares a React UI.

## Features

- **Source application:** MegaCRM (A)

- **Observed behaviour:** insert; LIKE query on name OR email with the caller's text.
- **Business logic:** name required, email unique.
- **Data requirements:** Contact.

- **Basis and confidence:** observed, high

### A-F02 Merge duplicate contacts

- **Source application:** MegaCRM (A)
- **Evidence:** A-E04
- **Description:** fold one contact into another.
- **Observed behaviour:** reassigns deals to the kept contact, then deletes the dropped one; no transaction visible; docstring mentions notes that do not exist.
- **Business logic:** destructive delete of the dropped contact.
- **Data requirements:** Contact, Deal.
- **Dependencies:** A-F01.
- **Integration requirements:** transactional persistence.
- **Basis and confidence:** observed, medium (docstring and code disagree on notes)

### A-F03 Deals pipeline (fixed stages)

- **Source application:** MegaCRM (A)
- **Evidence:** A-E06, A-E07, A-E08
- **Description:** deals with contact, title, value in cents and a stage.
- **Observed behaviour:** move_deal rejects unknown stages; any-to-any moves.
- **Business logic:** stages lead, qualified, proposal, won, lost.
- **Data requirements:** Deal, Contact.
- **Dependencies:** A-F01.
- **Integration requirements:** persistence.
- **Basis and confidence:** observed, high

### A-F04 CSV export

- **Source application:** MegaCRM (A)
